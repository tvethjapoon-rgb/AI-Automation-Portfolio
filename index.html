Automation that earns trust, not just clicks

I'm an AI automation specialist building practical systems for small and mid-size businesses — the kind where busywork eats the day and follow-ups fall through the cracks. My work centers on one belief: AI should draft, humans should decide.

Every system I build keeps a person in the approval loop, logs every action, and produces numbers the owner can actually read. My stack is built around n8n for orchestration, Supabase as the system of record, and familiar tools owners already use — Trello, Google Workspace, Airtable — so the automation fits the business instead of the other way around.

Shipped so far: AI call QA for support operations; Contractor's Office Autopilot for trade businesses; LeadScore Engine for lead scoring, quotation, and pipeline recovery. Queued next: inventory alerts for retailers and intake automation for law firms.

[03] // systems

Systems, not just automations

Agent-Run Production System for AI Content

target: SISTEMA — AI-assisted serialized drama production

LIVE

input: the problem

Content creators working with AI hit the same wall: characters drift between generations, assets get lost or overwritten, prompts are one-offs nobody can repeat, and there's no quality gate before anything ships. Scaling one good clip into a whole series breaks down into chaos.

output: the system

An ICM-structured workspace where the folder structure is the agent architecture. One source of truth for canon, a roster of specialist agents with explicit contracts, and a reviewer-gated task pipeline — so AI content production runs like a production line, with a human checking every stage.

// architecture

  • One folder, one job — every folder states its own purpose; the structure is the documentation.
  • Contracts per stage — each folder declares its inputs, process, outputs, and human check.
  • Agents are registered, not improvised — new agent types pass a promotion lifecycle (created → tested → validated → approved → trusted) before touching real work.
  • Reviewer-only closes — tasks move ASSIGNED → SUBMITTED → COMPLETED or REWORK; only a reviewer can close one.
  • Guardrails encoded — known model limits (face drift in video, fixed output lengths) are documented constraints the pipeline designs around, e.g. stills-first for character-critical shots.

pipeline stages

S01BIBLEcanon, character refs, style guide
S02Agents12 specialists, identity + capabilities
S03Tasksone folder per work item
S04Reviewcontinuity + acceptance gates
S05Outputslocked to agents, artifacts only
S06Human gatesplan, teaser, integrate approvals

// what it produces

  • Character reference sheets with identical faces across views, verified by face QA.
  • A season teaser run end-to-end through the pipeline: beat sheet → script → storyboard → video prompts, each stage gated.
  • Every asset traceable to the task folder that produced it — nothing appears from nowhere.
  • A repeatable pipeline: the next episode copies the pattern instead of reinventing it.
